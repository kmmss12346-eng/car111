# 机械臂 + 视觉闭环 + 整场任务（v4，2026-10-07）

STM32 和树莓派两边的代码。车到每个停车点后自动做：

```
QR    读二维码(GM65) → 解析任务码 → 串口屏显示
RAW   原料盘：按任务码颜色顺序，摄像头找到物料 → 闭环对准 → 夹起放进车上转盘 1/2/3 号槽
ROUGH 粗加工区：转盘里的物料依次放到指定圆环(摄像头对准圆环中心) → 再按顺序取回转盘
TEMP  暂存区：第一批平放在指定圆环；第二批码垛在同色物料上
START 回启停区：收臂，串口屏显示 抓取数/放置数
```

放圆环不是"看一次、动一次"，而是**边看边修的闭环**：摄像头测偏差 → 手臂(ID1/ID2)毫米级微调，偏差大才动底盘 → 等稳 → 再测，直到偏差小于 1mm（1 环要求 ±1.5mm）。
程序事先**不需要知道**摄像头朝哪、每毫米多少像素、ID1/ID2 每度多少毫米——会先用小动作自己测出来（探测），存下来下次直接用。

## ★ 底盘不动 / 转弯转不动：怎么查（v4 新增）

**这次日志的意思**：

```
S +42 -> DONE t=664 e=123      ← 前进/横移的 DONE 是按"该走多久"算的，STM32 不知道轮子到底转没转
F +83 -> DONE t=1330 e=24
R -60 -> DONE t=6838 e=-5780   ← 转弯要看陀螺仪：闭环转 5 秒超时 + 旧方法再试 6 次 ≈ 6.8 秒，最后车头还差 57.8°
```

也就是说 STM32 收到了指令、也发给了电机，但**车没转起来**（陀螺仪几乎没变）。`chassis.c` 和加机械臂之前**一个字都没改过**，`arm.c` 里只给 5 号地址(升降)发指令，碰不到 1~4 号轮子。所以先查**电机这一侧**：

1. **抬起车（轮子悬空）**，终端输入 `send R 90`：
   - 4 个轮子都转 → 通信和驱动器没问题，是**放到地上转不动**：电池电压低（最常见）、车装了机械臂变重了、轮子被卡。先充电/换满电的电池再试。
   - 有的转有的不转 → 看不转的那个驱动器的屏幕和接线。
   - 都不转 → 往下查。
2. **看 4 个驱动器的小屏幕**亮不亮、有没有显示堵转保护。**把电机电源关掉再开**（只重新烧录 STM32 不会让驱动器复位，堵转保护会一直在）。
3. **新接的升降驱动器**：先把它的串口线拔掉再试 `send R 90`。拔掉就好了，说明它接错了：地址要设成 **5**（出厂是 1，会和 1 号轮抢指令）；它的 TX 要接 STM32 的 RX(PC11)，**不能和 STM32 的 TX(PC10) 接在一起**（两个输出顶在一起，所有电机都收不到指令）。
4. 烧录新程序后输入 **`mot`**：读出 5 个驱动器各自的电压、有没有使能、有没有触发堵转保护，并用中文给出建议。`mot en` = 解除堵转保护并使能。
   （如果 5 个都"没有回复"，也可能只是驱动器的 TX 没接到 PC11：以前的程序只发不收，这根线可能本来就没接。那就以第 1 步的抬车测试为准。）
5. 还想排除新加的扫码/串口屏/PWM：`main.c` 里 `ARM_MODULES_ON` 改成 0 烧一次对比（另一个对话加的开关）。

**v4 程序做了什么**（帮您更快发现、自动恢复，底盘的运动算法没改）：
- 开机时、每次 `go`(HOME 指令)时，自动给 1~5 号驱动器**解除堵转保护并使能**。
- **转弯卡住检测**：按发出去的转速车早该转 90°、陀螺仪却没转出 3°，就判定轮子没转起来，**约 0.85 秒停车回 `ERR STALL`**（原来空转 6.8 秒还回 DONE）。正常转弯、反应慢的车、陀螺仪偶尔读错一帧都不会误判（电脑上用"假车"测过）。
- 树莓派：收到 `ERR STALL`、或者指令做完车头还差 10° 以上，**立刻停下**并在终端提示怎么查——不再带着错的车位接着扫描、建错地图、乱走。
- 新指令 `MOT?` / `MOT EN`（树莓派命令 `mot` / `mot en`）。
- 栈从 1KB 加到 4KB：编译报告里最深的调用链要 1016 字节(+中断)，原来的 1KB 不够（多出来的落在没用的堆里，所以以前没出事，但很危险）。

## 二、接线与模块设置

| 模块 | 接口 | 引脚 | 波特率 | 说明 |
|---|---|---|---|---|
| 扫码模块 GM65 | UART5 | PC12=TX → 模块 RX；PD2=RX ← 模块 TX | 9600 | 需要工作在**连续扫描**模式，扫到就自己发出，最好带回车换行(没换行也能识别，60ms 没新字节算收完) |
| 串口屏 TJC4832T135 | USART2 | PD5=TX → 屏 RX；PD6=RX ← 屏 TX | 9600 | 出厂 9600；改了就改 `arm.c` 里的 `SCREEN_BAUD` |
| 升降 | UART4 | Emm 地址 5，和轮子 1~4 同一路 | — | 回零方式见下 |
| 夹爪 / 转盘 | TIM2 CH3 / CH2 | PA2 / PB3 | — | |

先单独验证扫码模块：接电脑串口助手，看扫码时有没有输出、波特率是多少、有没有换行。**扫不出码、或者格式不是 `ddd+ddd+ddd+ddd`，整套流程都不会往下走。** 若 GM65 默认是按键/命令触发模式，需要用厂家设置码或上位机改成连续模式（我没有这个型号的手册，没法替您确认）。

**升降零点**：配置 `mission_cfg.lift_init`：
- `"zero"`（默认）：每次 `go` 一开始就把"现在的位置"记为 0(最低点)。**开机前必须把升降放到最低点！** 高度数字越大越高。
- `"home"`：让驱动器自己回零，要先在张大头驱动器里配好回零方式（限位开关/堵转）。
- `"skip"`：已经回零过，不再处理。

## 升降(5 号电机)：开机自动停到 60mm

- 高度约定：**0 = 最低点，往上为正，最高 100mm(写死)**。`arm LIFT 50` = 离最低点 50mm。
- **开机自动定位**：升降电机的编码器能读出"一圈里的角度"(一圈 = 40mm)。开机前把升降大概放在 **40~80mm 之间**，上电后程序读编码器算出准确高度，自动走到正好 60mm，不碰任何东西。跑完一轮回到启停区时，程序会自动把升降停回 60mm。
- **要先标定一次**(需要 5 号驱动器的 TX 接到 STM32 的 PC11，`mot` 里 5 号有电压显示)：
  1. 断开电机电源，用手把升降轻轻放到最低点，再上电；
  2. `arm LIFT CAL 0`(告诉程序"现在在 0mm")。它会往上 10mm 再回来，回复 `LIFTCAL OK …`，结果存进 STM32 的 Flash，断电、重新烧录都不丢；
  3. `arm LIFT 60`。以后每次上电都会自动停到 60mm。
- 检查：`arm LIFT ENC?` 回 `LIFTENC 读数 Z=编码器算的高度 NOW=程序记的高度`，两个数应该一样。
- 开机时串口会打印 `LIFTBOOT 47.3 -> 60`(找到的高度)；`LIFTBOOT NOCAL`(还没标定) 或 `LIFTBOOT NOENC`(读不到编码器) 时当作正好在 60mm，不动。
- 改开机高度：`arm.c` 里的 `LIFT_BOOT_MM`。

## 三、串口屏 HMI 工程

淘晶驰的屏**必须用它的 USART HMI 软件做一次工程、下载一次**（屏的固件和字库只有这个软件能生成，这一步没法用程序代替）。
但 v4 起程序会**自己往屏上画字**（参数 `SCRMODE=1`，默认），所以屏的工程里**不用放任何控件**，只要做下面几步：

1. 新建工程：型号选 T1 系列里的 `TJC4832T135_011`（没有就选 `TJC4832T035_011`），**横屏**（480×320）。
2. 菜单 工具 → 字库制作，做**两个字库**（字符集都选 ASCII）：
   - 第一个：高度 **20**（小字）
   - 第二个：高度 **80**（大字，赛规字高 ≥12mm）
   做好后在左下"字库"栏里**按这个顺序**添加：小字是 0 号，大字是 1 号。
3. 页面 page0 什么都不放（背景黑色即可）。page0 的"前初始化事件"里写一行 `bauds=9600`。
4. 编译、下载到屏（USB 转 TTL 下载，或生成 .tft 用 TF 卡）。
5. 接线：屏 TX → PD6，屏 RX → PD5，5V、GND。上电后屏上右上角显示 `READY` 就对了。

屏上的布局是程序定的（480×320）：

```
┌──────────────┬────────┐
│ 任务码前半    │ 阶段    │  大字(80px)
│ 156+123      │ 提示    │
├──────────────┤ 第一批  │
│ 任务码后半    │ 第二批  │  大字
│ 516+231      │        │
├──────────────┴────────┤
│ GRAB 6/6              │  大字(绿)
├───────────────────────┤
│ PLACE 12/12           │  大字(黄)
└───────────────────────┘
```

测试：树莓派终端 `arm SCR t0 156+123`，屏左上角应该出现大字 `156+123`。
想改位置/颜色：`arm.c` 里的 `scr_box[]` 表。想用回"写控件"的方式（工程里放 t0~t7 文本控件）：`set SCRMODE 0`。

## 五、上车调试顺序（照着做，不要直接 go）

先把车架空，轮子离地。树莓派终端里的命令（`arm …` 是直接发给 STM32）：

1. **通信**：`ping` → `PONG`；`get` 能看到机械臂参数；`mot` 看 5 个电机驱动器都有电、已使能、没触发保护；`send R 90` 看 4 个轮子都转。
2. **升降**：把升降放到最低点，`arm LIFT ZERO`；`arm LIFT 10` 看是不是往上 10mm。方向反了 `set LFDIR 1`；距离不对调 `LFPPM`（= 每圈脉冲数 ÷ 皮带每圈走的毫米数）。`LFMAX` 设成真实行程。
3. **夹爪/转盘**：`arm CLAW O`、`arm CLAW C`、`arm TT 1/2/3`。夹爪张开/夹紧的脉宽在 `main.c` 的 `CLAW_OPEN_US/CLAW_CLOSE_US`，转盘在 `TURNTABLE_*`。
4. **ID1/ID2**：`arm A? 1`、`arm AF 1 <度>`，找出这几个姿态并 `set`：
   `A1G A2E`(夹原料盘)、`A1D A2R`(转盘上方，缩回)、`A1P A2P`(地上圆环)、`A1H`(收臂待命)。
5. **高度**：`ZHI`(搬运高度，越高越安全但越慢)、`ZGRAB`(夹原料)、`ZDROP`(放进/取出转盘)、`ZPLC`(放圆环)、`ZSTK`(码垛，比 ZPLC 浅一个物料高度)、`ZOBRAW/ZOBRNG`(摄像头标定比例时的高度，通常等于 ZHI)。
6. **不用摄像头先试整套**：`set ARMOK 1`，然后 `arm GRAB 1`、`arm PLACE 1`、`arm PICK 1`。每个姿态都对了再往下。
7. **摄像头**：`vdbg RING` 存一张 `vdebug.png`，看绿十字(爪子位置)和黄圈(识别到的圆环)对不对。爪子位置不准就改 `mission_cfg.claw_px`（1 像素 ≈ 0.34mm）。
8. **视觉校准**：把车放在 ROUGH 停车点，`vcal RING`；原料盘物料放稳在画面里，`vcal RAW 1`(颜色号)。会自己动手臂和底盘几下，测出对应关系并存进 `servo_cal.json`，还会告诉您实测的像素/毫米比例。
9. **单工位测试**：`mtest QR`、`mtest RAW 1`、`mtest ROUGH 1`、`mtest TEMP 1`（需要先 `qr` 或 `mcode 156+123+516+231`）。
10. **整套**：先 `drive`/`go`，路线里只留第一批。

## 六、时间预算与提速

估算(电脑上模拟，**不含路线行驶**，按 `arm.c` 每个动作的步骤和速度参数累加)：

| 速度参数 | 只做第一批 | 两批 |
|---|---|---|
| 默认：LFRPM 150、ASPD 90、ASPDF 40、CLWAIT 400… | 280 秒 | 520 秒 |
| 提速：LFRPM 400、ASPD 270、ASPDF 120、ATOLC 2、CLWAIT 250、TTWAIT 600、LFMRG 100 | 143 秒 | 270 秒 |

调参建议（每次改一个，`set 名字 数值`，试稳了再往下调）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `LFRPM` | 150 | 升降速度，驱动器和电源允许的话往上调；最直接 |
| `ASPD` / `ASPDF` | 90 / 40 | ID1/ID2 大动作/微调速度(度/秒) |
| `ATOLC` | 1.0 | 大动作到位误差(度)，调大省时间 |
| `CLWAIT` / `TTWAIT` | 400 / 800 | 夹爪/转盘动作后等多久(毫秒)，调到刚好不松手 |
| `ZHI` | 120 | 搬运高度。升降每次抬到这里，**数字越大越高**；越低行程越短越快，够清过物料(60mm高)和转盘边就行 |
| `LFMRG` | 200 | 升降走完多等多久(毫秒) |
| `ATOL` | 0.3 | 微调到位误差(度)。如果 `AP`/`AD` 总是等满超时(每次多等近 1 秒)，说明舵机到不了这么准，调大一点(0.5) |
| `mission_cfg.frames` | 5 | 摄像头每次测几帧，少一点快一点 |
| `mission_cfg.pickback_order` | `code` | 粗加工区取回顺序：`near` 底盘走得最少(省时间)，但不是按任务码顺序 |

`time_limit_s`(默认 150 秒)：超过它就不再夹放，让车尽快回启停区。计时从 `go` 开始，包含扫描和规划。
**注意**：时间到以后路线还是会一站一站走完（只是不做夹放），所以第二批做不完时，最省时间的办法是路线里直接不排第二批。

## 七、赛规相关的风险（请对照赛题确认）

- **粗加工区"放下再取回"**：赛题规则第 4 条写"物料底面一旦与地面接触即视为放置完毕……若再次移动此物料，本轮比赛结束"，但流程描述又明确要求把粗加工区的物料取回车上运到暂存区。我按**流程描述**做；规则 4 对取回的解释请您对照赛题/问裁判确认。
- **圆环编号方向**：配置 `ring_offset_mm` 里 ROUGH 默认"1 号环在车头前方(东)，3 号在后"，TEMP 默认"1 号在后方、3 号在前方"(按图纸方向推的)。**到现场看圆环里印的数字核对**，反了就把对应区的正负号对调，否则物料会放到错误的圆环。
- **15 秒不动**：等原料盘最多 10 秒(`raw_wait_s`)，等二维码最多 6 秒(`qr_timeout_s`)；手臂动作算不算"运行"赛题没写清，请确认。
- **一键启动**：v14 的 `go` 流程在出发前要在终端输入 `y` 确认，这和"一键启动、不能接触电脑"冲突，需要换成实体按钮（本次没做）。
- 抓取/放置的"正确数量"是**指令执行成功且对准误差在容许范围内**的次数，没有传感器确认真的夹到了/放到了。
- 夹爪按位置控制，没有"夹到没有"的检测。

## 八、常见问题

| 现象 | 原因和办法 |
|---|---|
| 车不动 / `ERR STALL` / "车头还差 xx°" | 轮子没转起来。见开头"底盘不动 / 转弯转不动：怎么查"：抬车 `send R 90`、`mot`、充电、电机电源关了再开、拔掉升降驱动器的串口线试 |
| `mot` 全部"没有回复" | 驱动器没电，或驱动器的 TX 没接到 STM32 的 PC11(以前只发不收，可能本来就没接)；以抬车测试为准 |
| `ERR NOCAL` | `ARMOK` 还是 0。标定好姿态后 `set ARMOK 1` |
| `ERR NOZERO` | 升降没回零。`arm LIFT ZERO`，或配置 `lift_init` |
| 整轮不夹，屏上 `ARM OFF` | 同上，看终端里"本轮不做夹取/放置：…"那一行的原因 |
| 屏上 `QR FAIL` | 扫码模块没出码：检查 UART5 接线、9600、连续模式、码板距离 |
| `看不到目标` | 摄像头没拍到：`vdbg` 看画面；原料盘还没转到；`claw_px` 位置不对 |
| `发散…需要重新校准` | 动作方向和画面对不上(摄像头/机构变过)：`vcal RING` / `vcal RAW <颜色>` 重新校准 |
| `探测失败` | 动了手臂/底盘但画面没变：检查目标是不是真的在画面里、`AP`/`S`/`F` 有没有真的动 |
| 放置总是偏向同一个方向 | 调 `mission_cfg.claw_px.RING`(往偏的反方向挪几个像素) |
| 屏不显示 | 开机右上角没有 `READY`：查接线(屏 TX→PD6、RX→PD5)、波特率 9600、两个字库(0 小 1 大)有没有加进工程；再 `arm SCR t0 123` 试一条 |
| 急停后升降动不了 | 急停打断升降后位置不明，要重新 `arm LIFT ZERO` |
