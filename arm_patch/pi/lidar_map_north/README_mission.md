# 树莓派端：机械臂任务 + 视觉闭环

总说明（赛规风险、接线、串口屏、STM32 安装、上车调试顺序）在上一级的 `../../README.md`，先读那份。这里只讲树莓派端。

## 文件

| 文件 | 作用 |
|---|---|
| `mission_hooks.py` | **整场任务**：挂在 `auto_run.drive` 每个停车点上，按停车点分发 QR / RAW / ROUGH / TEMP / START |
| `visual_servo.py` | **摄像头闭环对准**：测偏差 → 动 ID1/ID2(精调)或底盘(粗调) → 再测；自己探测动作和画面的对应关系 |
| `vision.py` | 摄像头(只开一次，后台线程一直取最新一帧)、爪子点/物料半径标定文件 `vision_cal.json` |
| `matdet.py` | 物料识别(抗爪子遮挡)：只用没被挡住的那段圆边拟合整个圆，被挡住 80% 圆心也只差 1~2 像素；颜色范围用 `wuliao.py` 里的 |
| `ringdet.py` | 圆环识别(抗爪子遮挡)：每段边缘拟合圆弧，同心的合成一个圆环，被挡掉一截也能认，圆心误差零点几像素 |
| `vlive.py` | 摄像头实时预览(在树莓派桌面终端运行，自己开摄像头，map_merge_live 要先退出)：画出识别到的圆、爪子区域、离爪子点多少毫米 |
| `vview.py` | 实时看 map_merge_live 正在用的摄像头画面(rtest / gtest / mtest / vclaw / go 时)，不用退出 map_merge_live |
| `arm_link.py` | STM32 机械臂指令封装、给视觉闭环用的手臂/底盘动作(含底盘位移记账)；新程序的 `PARK`、`ZONE?`/`ZONE …`、`LIFT?` 里的 `BOOT=`(旧程序不认识时自动退回老办法) |
| `task_plan.py` | 任务码解析、每批物料的颜色/圆环/转盘槽位、码垛目标(同色匹配) |
| `mission_cli.py` | 终端测试命令：`arm` `qr` `mcode` `vmask` `vclaw` `vcal` `vdbg` `gtest` `mtest` `mot` |
| `apply_mission_config.py` | 给配置文件加 `mission_cfg`(只补缺的，自动备份) |
| `route_plan.py` | v14 的路线规划，加了**离黄色区硬性余量** `yellow_margin_mm`(默认 30)：某段按 30mm 走不通(如 400mm 宽的中间车道)时这一段自动减半/放到 0 并在终端提示 |
| `auto_run.py` `map_merge_live.py` | v14 的文件，各加了几行(见 `../v14_integration.patch`)；v4：车没转到位(`ERR STALL`/车头还差 10° 以上)时停下并提示 |
| `sim_mission.py` | 整场模拟(假 STM32 + 假摄像头 + 物理世界)，也能估算用时 |
| `test_*.py` | 单元测试(`test_mission_api.py`：给导航的接口、扫码前后挪着找、PARK/ZONE) |

## 安装

1. 把本文件夹里的文件复制到树莓派的 `lidar_map_north/`。`auto_run.py`、`map_merge_live.py` 会**覆盖**您现有的同名文件——它们基于 v14。如果您的版本比 v14 新，不要覆盖，用补丁(在 `lidar_map_north` 的**上一级目录**运行)：`patch -p0 < v14_integration.patch`，补丁文件是 `../v14_integration.patch`，一共 3 处小改动：
   - `auto_run.drive`：开头加 `hooks.ctx = ctx`（让任务钩子能检查 abort）
   - `map_merge_live.mission_thread`：配置里 `mission_cfg.enabled` 为 true 时创建 `MissionHooks` 并传给 `run_mission`
   - `map_merge_live.command`：加 `arm vcal mtest vdbg qr mcode mot` 几个命令
   - v4 `auto_run`：第二站或路线里某条指令回 `ERR STALL`、或做完车头还差 10° 以上，马上停下并提示怎么查(以前会带着错的车位继续扫描、走路线)
2. 把 `chengxu` 里的 **`wuliao.py`** 复制到这个文件夹(物料颜色范围用它里面调好的；没有就用 matdet.py 里一样的默认值)。
3. `python3 apply_mission_config.py`。
4. 需要 `numpy` 和 `opencv`（树莓派上识别代码本来就要用）。
5. 跑测试确认环境没问题：`python3 -m unittest test_task_plan test_visual_servo test_vision test_mission_cli test_mission_api test_auto_run test_route_margin sim_mission`

## 每个停车点做什么

停车点名字按前缀匹配角色：`QR`、`RAW`、`ROUGH`、`TEMP`、`START*`（和配置里 `stops`/`mission` 的名字一致；名字不同就配 `stop_aliases`，如 `{"ROUGH": ["PROC"]}`）。同一个角色第几次到，就是第几批。

**出发前(导航调 `prepare`)**：机械臂初始化、收臂(STOW)、同步参数；**`QR CLR` 清掉 STM32 里存的旧任务码**(上一轮或调试时扫过的码会一直存着，
不清的话到 QR 点第一次 `QR?` 就拿到旧码，整轮搬错)；屏上任务码先显示 `---`；打开摄像头。出错只提示，不影响出发。

**QR**：先原地查 `qr_first_wait_s`(0.6)秒(路上可能已经读到了)。读不到就**沿车道前后挪着找**：
- 扫码器装在车的**右后方**(离车尾 20mm、离右边 40mm，也就是车中心后 125mm、右 90mm)。QR 停车点 (2100,1200) 车头朝北时扫码器在 y≈1075，
  码板中心每场随机在 1100~1300，所以停在停车点时多半对不准。
- 依次让扫码器对着码板的 1200、1260、1140、1320(`qr_targets_mm`，1080 和停车点差不多就不挪)：车头朝北时底盘前进 125、185、65、245mm，
  每个位置停 `qr_dwell_s`(0.8)秒查 `QR?`，读到就停。按停车点的车头方向算，车头换了方向也对。
- 每挪一次之前检查车身(含雷达)扫过的地方：离地图上的障碍物不到 `qr_obstacle_margin_mm`(60)、离黄色区/工位/原料转盘/场地边不到
  `qr_zone_margin_mm`(30)就跳过那个位置(导航的 route_plan 有 `moves_clear` 时也让它查一遍)。只前后挪，不横移。
- **不管读没读到，最后都挪回停车点**(后面的路线是从停车点算的)。急停时不再动。
- 新的 STM32 程序在车走的时候读到的码也存着：路过码就算数。
- 还是没读到：屏上 `QR FAIL`；后面每个停车点再问一次 `QR?`(读到了照常做)；到过 QR 点还是没有任务码，导航问"要不要回家"时直接回家(`home_when_idle`)。
- 屏上任务码分两行，**带上两组之间的 +**：t0 = `156+123+`，t7 = `516+231`(`code_plus`；屏上放不下 8 个大字就改 false)。

**RAW**（每个物料）：
`OBS RAW O`(手臂摆到原料盘上方、张开夹爪) → 盯着这个颜色的物料(一帧一帧认，同时看整个画面在不在动) → 原料盘**一停下**、物料在爪子附近：马上对准(只用 `vcal RAW` 存好的手臂-画面对应关系，一下修到位，最多 `raw_max_iter` 次，不现测) → **这一次停下必须下爪的时刻一到就不再修**，按当时的偏差下爪(不超过 `raw_grab_max_mm`) → `GRAB n H`(下降夹紧、抬起、转到转盘上方放进 n 号槽)。
原料盘大约转 3 秒停 6 秒(不一定准)：每次停、转多久都从画面实测，按实测的估计这一次停下还剩多久；剩的时间不够(对准 + 下爪到夹住)、停在手臂够不着的地方、对准中途转起来了，都回到 OBS RAW 姿态等下一次停，最多等 `raw_track_s` 秒。对准默认**只动手臂、车轮不动**(`raw_chassis='off'`，不会压进原料区)。
**要先让原料盘停转做一次 `vcal RAW <颜色> arm`**：转盘一停一转时不现测(几秒钟测不完，转起来还会测错)；看到原料盘连续 `raw_static_s`(9)秒都不转(关了)才现测。

**ROUGH / TEMP 到工位先做的事**：
- (只在 `mtest` 里)`HOME`：把现在的车头方向记为要保持的方向。车是手搬过来的，不记的话底盘一前后挪就把车头往开机时的方向转。
- **看清三个圆环**(`ring_survey`)：`OBS RING O`，拍一次画面找出所有圆环，按排列认出 1、2、3 号(画面里从左到右的顺序见 `ring_order`；
  看到三个直接认；两个看哪一头没有环；一个当作 2 号)，算出"每个环正对爪子时底盘要前进/后退多少"。
  第一次还会底盘前进 20mm 再退回来，看画面往哪边动(存进 `servo_cal.json`，以后不再测)。顺便用圆环间距(`ring_spacing_mm`=150)算每毫米多少像素(没做 `vclaw RING` 时用它判断误差)。
  车要停在 **2 号环正对爪子、车身和圆环那一排平行**；停偏 75mm 以上(画面里只看到两个环、离爪子都远)会提示"认不准"。

**ROUGH**：
- 放(按任务码顺序，每个物料)：底盘沿圆环那一排前后挪，一条指令开到这个环(按看到的位置) → `OBS RING O`(**空爪**到圆环上方) → 闭环对准圆环中心
  (只认这个环，不去追旁边那个；**先用手臂**，沿这一排差 18mm 以上才前后挪底盘、最多 `ring_fix_max_mm`；
  离圆环远一点近一点靠 ID2 伸缩补，**伸缩到头还够不着，车轮才横着靠近/退远**，只挪够不着的那一段，离停车点累计不超过 `ring_strafe_max_mm`)
  → 白心里已经有东西就不放 → 记下 ID1/ID2 角度 → `TAKE n`(去转盘取) → `AP`(回到记下的角度)
  → 下降到 `ZPLC`、松开、抬到 `ZHI`(**不缩回**、不回去拍照，直接去下一个环；`drop_retract=true` 改回用 `DROP`)
  先用空爪对准是因为圆环不会被手里的物料挡住，而且舵机回到同一个角度的重复精度很高。
  取出物料以后出错(回不到姿态、下降失败)：先把物料放回它的转盘槽再收臂，不会夹着物料到处走。
- (`learn_pick=true` 时)第一次放下物料后回去量 PICK 点(物料在爪子正下方时它顶面圆心在画面里的位置)，取回时直接认物料。默认关(要多拍一次)，取回认圆环外圈。
- 取回(按 `pickback_order`)：底盘回到放下时的位置(只前后) → `AP` 回到放下时的角度 → 白心被物料盖住：量过 PICK 点就认物料顶面，否则认圆环外圈(放物料时记下了空圆环的大小)
  → 都认不到就回到放下时的位置直接夹 → `PICK n H`
- 做完先 `STOW`(收臂)，再把底盘挪回停车点。

**TEMP**：第一批和 ROUGH 的放一样(平放)；第二批找同色的第一批物料，先认它的顶面对到 PICK 点(认不到就认圆环外圈；都认不到不放，免得砸倒下面那个)，下降到 `ZSTK`(浅一个物料高度)。
**第一批那个没放成功(没有同色物料可叠)：不放、不算放置，物料留在车上**——规则规定第二批在暂存区只能码垛在同色物料上，平放 0 分还白花十几秒(以前会平放到空环)。

**转盘槽被占着**：前面没放出去的物料还在某个槽里，第二批同一个槽的物料就不夹(放进去会砸在上面)，也不会把它当成第二批的去放。

**START**：收臂、升降停到 60mm(新程序用 `PARK`，旧程序 `STOW` + `LIFT 60`；爪子里可能夹着物料时不降)，屏上显示 `DONE`、
**`GRAB n`、`PLACE m`(只写做成的个数，不写成 3/3 这种分数，裁判一眼看清)**、用时；终端打印每次放置的对准误差和每个停车点用了多久。

**时间(3 分钟一轮)**：
- 计时从**按下 START(导航调 `start_clock`)**开始，不再从创建钩子开始(以前把扫描、规划、等人摆车的时间都算进去了)。
- 每个物料开始前算：这个物料大约要多久(实测的；没实测过按 `work_item_s`) + 收臂挪回 + 回家(导航告诉的 `set_home_eta`) + 余量 `home_margin_s`(12 秒)，
  超过 `round_s`(180)就不开始，屏上 `TIME UP`，记下"时间不够"，**不抛异常**，导航从这里直接回家。也不超过 `time_limit_s`。
- 粗加工区放完以后算一下：取回了还来不来得及去暂存区放下再回家；来不及的就不取回(放下时已经算分了，留在粗加工区不吃亏，车早点回家)。
- 导航开往下一个停车点之前问 `go_home_now`：去了至少做完一个物料再回家来不来得及，来不及就直接回家。

**车身和圆环那一排不平行(车停斜了)**：看三个环时比较"底盘前进时圆环在画面里怎么动"和"三个环连线的方向"，算出车身斜了几度，
**每次都在终端报角度，3° 以上打 ★ 提醒"把车摆正"**。斜 5° 时挪到隔一个环的地方离圆环远近差 13mm、隔两个差 26mm：
提前补到手臂伸缩上(`tilt_precorrect`)，第一次测量时只差一两毫米(模拟：提前补最大 3mm，不补平均 18mm)。
第一次换环(挪 100mm 以上)时再看一眼画面，把角度量准(存进 `servo_cal.json`，以后到工位直接用)，顺便手臂直接转到这个环上。

**先动车轮还是先动手臂**(用户问过的"到了附近先小幅慢速动轮子找，实在不行再动爪子")：做成了开关 `wheels_first`，默认关，
`mtest TEMP 1 force wheels` 可以只这一次先动车轮，和默认的比一比用时、准不准(结束时打印"这次用时")。默认先动手臂的原因(模拟 20 组)：
- 车轮只能沿圆环那一排前后挪，离圆环的远近还得靠手臂伸缩，手臂的步数省不掉；
- 车轮只能按整毫米走，小步实际误差 ±1mm，并不比手臂准(ID1 最小一步约 0.9mm)；STM32 按加减速走 15mm 时最高也就三十几转/分，`wheels_rpm` 管不了"慢"；
- 结果先动车轮两批多用约 26 秒、失败多一些。
"放两次太浪费时间"那部分：每个物料必须"转盘→环、环→转盘"各大幅转一次，先对准再去取物料和先取物料再对准，大幅转的次数一样(都是 2 次)，
真正耗时的是 ID2 大幅伸缩和升降；提速参数(`sim_mission.py fast`)能把一整场的夹放从 420 秒降到 230 秒左右。

## 配置 `mission_cfg`（在 `map_config_start2_roi.json` 里）

`apply_mission_config.py` 会把默认值全写进去，您改自己要改的：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | false = `go` 时不做夹放，只走路线 |
| `time_limit_s` | 150 | 超过这个时间不再夹放(每个物料要在这之前做完)。计时从按 START 开始(`start_clock`) |
| `round_s` / `home_margin_s` / `stop_finish_s` | 180 / 12 / 3 | 一轮多长 / 算"来不来得及回家"时多留的秒数 / 停车点做完收臂挪回要多久 |
| `work_item_s` | grab 12、place 10、pick 8、stack 10 | 每个物料大约要多久(秒)，跑过就按实测的 |
| `work_base_s` / `next_leg_s` | QR 3、RAW 2、ROUGH 6、TEMP 5 / 12 | 每个停车点物料以外的用时 / 粗加工区开到暂存区要多久 |
| `home_when_idle` | true | 到过 QR 点以后再也没活可干(没读到码、机械臂不能用)：导航问的时候直接回家 |
| `qr_search` / `qr_first_wait_s` / `qr_dwell_s` | true / 0.6 / 0.8 | 读不到码时前后挪着找 / 到了先查多久 / 每个位置查多久 |
| `qr_targets_mm` | [1200, 1260, 1140, 1320, 1080] | 扫码器依次对着码板的哪些位置(沿码板方向的场地坐标) |
| `qr_scanner_from_rear_mm` / `qr_scanner_from_right_mm` | 20 / 40 | 扫码器装在车右后方：离车尾、离右边多少毫米 |
| `qr_board_axis` / `qr_max_move_mm` | `y` / 300 | 码板沿哪个方向摆(东墙 = y) / 找码时离停车点最多挪多少 |
| `qr_obstacle_margin_mm` / `qr_zone_margin_mm` | 60 / 30 | 找码挪车时离障碍物 / 黄色区、工位、转盘、场地边至少多远 |
| `qr_move_rpm` / `qr_retry_at_stops` | null / true | 找码时底盘速度(null = 默认) / 后面的停车点再问一次 QR? |
| `code_plus` | true | 屏上任务码带 +(t0 = 前两组加 +) |
| `keepalive_deg` / `keepalive_min_s` | 3 / 5 | 导航在车长时间不动时调 `keepalive`：ID1 摆几度再摆回来 / 两次至少隔多久 |
| `tilt_precorrect` / `tilt_warn_deg` | true / 3 | 车身斜了提前补手臂伸缩 / 斜到几度打 ★ 提醒 |
| `qr_timeout_s` / `raw_wait_s` | 6 / 10 | 等二维码 / 等原料盘停稳最多多久 |
| `raw_track_s` / `raw_stop_s` | 30 / 4 | 每个物料最多等多久(秒) / 没实测到之前按原料盘每次停多少秒算(保守一点)；实测到以后按实测的，还按"停多久+转多久"的周期推算每次停下的时刻 |
| `raw_still_px` / `raw_motion_frac` | 6 / 0.004 | 物料一帧和前两帧比变了不到这么多像素 = 没在动 / 看不到物料时：画面(爪子以外)变了的比例超过它 = 原料盘在转 |
| `raw_frames` / `raw_max_iter` / `raw_gain` | 1 / 3 / 1.0 | 原料区对准时每次测量用几帧 / 最多修正几次 / 每次修掉偏差的多少(用 vcal 测好的 J 一下修到位) |
| `raw_grab_max_mm` / `raw_tol_mm` | 5 / 3 | 停的时间到了就按当时的偏差下爪，只要不超过这个(爪子每边约 5mm 余量) / 对准到这么小就马上下爪(夹爪合上会把物料夹正) |
| `raw_any_order` | false | true = 不按任务码顺序：每次停下，要抓的颜色里哪个在爪子附近就先夹哪个(放进它自己的槽)。**规则按任务码顺序算"正确抓取"的 2 分**，不按顺序可能拿不到这 2 分(放置分不受影响)。只试一次：`mtest RAW 1 any` |
| `raw_keepalive_s` | 12 | 等物料转过来时手臂这么多秒没动就轻轻摆一下 ID1(规则：停止运行 15 秒、等转盘 23 秒本轮结束) |

| `qr` | 读 STM32 里存的任务码 |

| `vclaw RAW <颜色号>` | 实测原料爪子点：原料盘停住、物料放在爪子正下方。会降下去夹正、松开、升回去测，两遍一致才存 |

| `vclaw PICK` | 清掉物料顶面的爪子点(PICK)，下次放下物料时重新量。摄像头/爪子动过、改过 `ZOBRNG` 时用(改了 `ZOBRNG` 程序也会自己发现) |

## 视觉闭环怎么工作的

`visual_servo.py`：`p = 目标像素 − 爪子像素`。

- **雅可比 J**：每个单位动作(ID2 转 1°、ID1 转 1°、底盘 S/F 1mm)让目标在画面里移动多少像素。第一次(或发现对不上时)用小动作探测：动一下、看画面变化、算出 J；存进 `servo_cal.json`，下次直接用。探测步长自动加大到画面变化够测准为止；目标靠近画面边缘时用更小的步长，保证不会探测到目标出画面。
- **修正**：`Δ动作 = −J⁻¹·p × 增益`。偏差 ≤ 18mm 用手臂(精度高)，更大或手臂行程不够用底盘。粗加工区/暂存区里：只有沿圆环那一排差 18mm 以上才前后挪底盘，横向(离圆环远近)的偏差先靠 ID2 伸缩，伸缩到头还差才让车轮横移那一段(`chassis_axes='Fs'`)。
  每次修正后用实际移动量在线微调 J(按每个轴让画面动了多少像素分摊，ID2 每度只动零点几像素，不会被测量噪声带偏)。
  离目标很近(容差的 2 倍以内)时先再测一次取平均再决定动不动，不去追测量噪声。
- **保护**：误差反而变大 → **先再测一次**(一次测量跳一下不算，滤波开着时看滤波后的值)，复测还是大才算发散 → 丢掉 J 重新探测，再发散就放弃；
  发散时丢掉的 J **只在这次运行里不用**，不从 `servo_cal.json` 里删(比赛中一次误判不会把 vcal 测好的弄没)；
  手臂相对观察姿态的总偏移有上限(提前伸缩过的话，按机构的行程算还能往哪边转多少；伸缩到头剩下几毫米也让车轮横移，不会卡住)；
  每步动作量、总时间都有上限(第一次探测 J 的时间不算进超时)；对准失败的物料跳过，不乱夹。

`mission_cfg.servo` 可以覆盖：`max_iter`(6)、`timeout_s`(10)、`gain_arm`(0.85)、`gain_ch`(0.8)、`settle_arm_s`(0.2，手臂动完等多久再拍)、`settle_ch_s`(0.35)、`arm_limit_deg`({id2:250, id1:12})、`step_limit_deg`({id2:90, id1:4})、`chassis_axes`('SF'；工位里自动用 'F')、`near_avg`(2.0)、`arm_cover_mm`(18)、`chassis_min_mm`(6)、`confirm`(true，达标后再测一次确认)等，名字和含义见 `visual_servo.py` 开头的 `DEFAULTS`。

**怎么判断校准对不对**：`vcal RING` 会打印"ID2 每转 1° ≈ x mm、ID1 每转 1° ≈ y mm、实测 z 像素/毫米"。ID1 约等于(臂长 × π/180)毫米/度(臂长 150mm 时约 2.6)，ID2 约等于齿轮分度圆周长/360。数量级对不上，说明摄像头没拍到目标或者机构有问题。

## 出错时的行为

| 情况 | 行为 |
|---|---|
| `ARMOK=0` / 没回零 / STM32 里没有机械臂参数 | 整轮不做夹放，路线照走，屏上 `ARM OFF` |
| 没读到二维码 / 内容不对 | 整轮不做夹放，屏上 `QR FAIL` / `QR BAD` |
| 某个物料看不到、对不准、STM32 回错误 | 跳过这个物料，`STOW` 收臂(收臂偶尔出错再收一次)，继续下一个 |
| 停车点里出了意外的错(程序 bug 之类) | 这个停车点不做了：收臂(夹着物料先放回转盘)、底盘挪回停车点，**路线照走，不结束这一轮** |
| 时间不够 | 不再开始新的物料，屏上 `TIME UP`，导航从当前停车点直接回家(不抛异常) |
| 已经从转盘取出物料以后出错 | 先把物料放回它的转盘槽再收臂；放回也失败：爪子保持夹紧收臂，本轮不再夹放 |
| 收臂也失败 | 抛 `Abort`，路线停止（带着伸出的手臂乱走不安全） |
| 终端输入 `abort` | STM32 停升降，当前动作回 `ERR ABORT`，钩子抛 `Abort`，路线停止 |
| 转弯时轮子没转起来(`ERR STALL`)，或者指令做完车头还差 10° 以上 | 路线马上停止，终端提示：`mot` 看驱动器、抬车 `send R 90`、充电、电机电源关了再开 |
| 急停以后 | 不自动收臂、不降升降(人手可能在附近)；确认安全后输入 `park` |

## 给导航的接口(`MissionHooks`，导航都先 `hasattr` 再调，旧导航不调也照常能跑)

| 接口 | 什么时候调 | 做什么 |
|---|---|---|
| `prepare(link, log)` | 按 START 以后、第二站动作之前(要在 `ZONE LOCK` 之后) | 机械臂初始化 + 收臂、同步参数、`QR CLR`、屏上任务码 `---`、打开摄像头。调多次没关系，出错不抛异常 |
| `start_clock()` | 按下 START 的那一刻 | 比赛计时从这里开始 |
| `time_left()` | 随时 | 离 `time_limit_s` 还有多少秒 |
| `set_home_eta(秒)` | 每到一个停车点、`task` 之前 | 从这个停车点回家要多久(路线估算)：停车点里每个物料开始前按它算来不来得及 |
| `go_home_now(下一个停车点, 开过去几秒, 从那里回家几秒)` | 开往下一个停车点之前 | True = 去了做完一个物料就来不及回家(或者后面没活可干)，从这里直接回家 |
| `keepalive()` | 车长时间不动(扫描、规划、雷达定位)时，任务线程里 | ID1 摆 3° 马上摆回来(不到 1 秒)，5 秒以内只摆一次；机械臂没就绪就什么也不做 |
| `park(link=None, force=False)` | 跑完(START 自己会调)、退出程序时 | 收臂、升降停 60；夹着东西不做；急停过不做(除非 force) |
| `task(停车点, link, log)` | 到每个停车点 | 和以前一样；`ctx.obstacles()` 有的话找码时用它避障 |
