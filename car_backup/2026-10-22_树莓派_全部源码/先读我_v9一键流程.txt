v9（2026-10-02）一键流程：scan -> STM32走第二站 -> second -> 规划 -> 确认后按路线行驶

一、新命令（树莓派终端）
  go     车放启停区2、车头朝北、停稳后输入。依次：
         PING/HOME STM32 -> 第一次扫描 -> 让 STM32 走第二站(P2) -> 第二次扫描 ->
         规划全程路线 -> 打印路线并等你输入 y -> 按路线一条一条发给 STM32 并等 DONE
  y / n  确认开始行驶 / 取消（没发过任何运动指令）
  abort  行驶中输入：当前这条指令做完后停止（要立刻停车请断电）
  drive  不重新扫描，只按已规划好的路线行驶（走到一半失败后可以重试，但车要先放回规划起点）
  ping   测试和 STM32 的通信
  p2     只让 STM32 走第二站

二、串口
  默认 --stm-port /dev/serial0（和以前读 YAW100 是同一个口）。有了它就不再单独启动 GyroReader，
  YAW100 由同一个串口通道读取，所以不要同时开别的读 /dev/serial0 的脚本。
  不接 STM32 只想看规划：bash run_live.sh --stm-port none
  桌面模拟整个流程：bash run_live.sh --sim，然后输入 go 再输入 y

三、协议（每条一行文本，115200）
  树莓派 -> STM32:  PING | HOME | P2 | F <mm> | S <mm> | R <度> | YAW?
      F 前进(负数后退)   S 横移(正数向左)   R 原地转(正数逆时针)
  STM32 -> 树莓派:  DONE | ERR <原因> | PONG | READY | YAW100 <角度x100>
  同一时间只发一条，收到 DONE 才发下一条。失败或超时就停止，不再往下发。

四、说明
  - 小于 20mm 的前进/横移不发（车本身精度就在这个量级，发了只会多一次起停）。
  - 路线里“到达 XXX”的位置，以后放抓取/放置动作（auto_run.py 的 drive 函数里）。
  - second_pose_mm=[2208,233,33] 是在旧版 STM32 动作下测出来的。STM32 的移动参数改过
    （比如平移加速度）以后，第二站实际位置可能变了，要重新测；删掉配置里的 second_pose_mm
    就按转轴模型推算。
  - 只在电脑上用模拟的 STM32 和模拟的雷达跑通了流程，还没有实车验证。

v9.1（2026-10-02 晚）
  - 每个停车点现在是：到达 -> 姿态纠偏（还没接摄像头，先跳过）-> 执行任务（先停几秒代替）。
    停多久：bash run_live.sh --stop-wait 5   （默认3秒）
  - 以后接入：auto_run.py 的 drive() 里有 hooks.adjust(stop, link, log)（用导航摄像头把车摆正，
    通过 link.move('F'/'S'/'R', 毫米或度) 发小动作）和 hooks.task(stop, link, log)（抓取/放置/读二维码）。

v9.2（2026-10-02 晚）
  - 规划器尽量不走横移：横移每走一格按 strafe_cost_factor(默认6) 倍代价算。同一组障碍物，
    横移总长从 12150mm 降到 6800mm，前进/后退相应变多。想改力度：在配置里加 "strafe_cost_factor": 数字。
    横移不可能完全没有：车道只有400mm宽、转弯半径约281mm，到作业区常常转不开，只能横移过去。

==== v9.3 ====
路线规划改为"走路用直行/后退，横移只做微调"：
 - 每一段路线里横移累计不超过 strafe_max_mm_per_leg（默认 300mm，map_config 里可改）。
 - 如果在这个限制下规划不出路线(障碍物布局逼着长横移)，自动放宽限制重新规划，
   并在预览里打印 ⚠ 警告，告诉你这条路线含长距离横移，行驶前请自己判断。
 - turn_pivot_back_mm(转轴在车中心后多少mm)越小，越容易规划出"只直行不横移"的路线。

v10（在 v9 基础上）
  - 修复：用中文输入法打的全角字母/空格（如ｇｏ）现在也能识别。上次 go 提示“未执行”就是这个原因。
  - 新命令 send：单独发一条运动指令测试通道，等 STM32 回 DONE：
      send F 300    前进300mm（负数后退）
      send S -150   横移（正数向左，负数向右）
      send R -90    原地转（正数逆时针）

v11（在 v9/v10 基础上，路线规划）
  - 爪子在车右侧：停车点车头方向改为 工位方向+90°。二维码→车头朝北；原料→朝西；粗加工→朝东；暂存→朝南。
    车沿着靠工位的车道直行过去，到了爪子正好朝着工位。停车点离边线仍按300mm，要按爪子够得着的距离调。
  - 原地转弯按车身实际扫过的范围判断（每5°一个车身矩形），不再要求一整圈都空着：
    能转弯的位置从约40个增加到约1600个，“只走直行”的路线容易规划出来了。
  - 每次只转90°，两个90°不合并成180°（避免STM32朝另一边转、扫到没检查过的地方）。
  - 少倒车：倒车每格按1.5倍代价算（看路摄像头倒车时看不到前方）。
  - 横移每段≤300mm（strafe_max_mm_per_leg），横移代价3倍、每次90°转弯代价500（strafe_cost_factor、turn_cost_mm）。
  - 仿真（你实测的障碍物布局）：v9 需要放宽横移（共3.95m、单段1.05m）、倒车12.5m；
    v11 横移共约1m（单段≤200mm）、倒车约3m、转弯16次，估计行驶约85秒。
    用转轴模型模拟每条指令，8个停车点全部准确到达。
