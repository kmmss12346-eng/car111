# v14：到 QR 再扫一次障碍物 + 回启停区前先用雷达定位

只改树莓派，STM32 不用重新烧，你调好的参数和配置一个都没动。包含 v11~v13 的全部内容，直接装这个就行。

## 1. 左上角障碍物扫不到 → 到 QR 再扫一次

左上角离启停区 2.5 米左右，是全场离雷达最远的地方。雷达被碰歪一点、阳光强一点、圆柱放远一点，都可能一个点都收不到。光靠起点那两次扫描，比赛时不保险。

现在车到 QR 停车点(本来就要停下读二维码)时会再扫一次。QR 在场地右边中间，离左上角只有 1.75 米左右，车头朝北，雷达正对着场地左半边，看得清楚得多。
- 没有新障碍物：按原路线继续，不多花规划时间(只多扫描 4 秒左右)。
- 发现新障碍物：加进地图，从 QR 重新规划剩下的路线(有障碍物的车道照样整段封死)，再继续走。树莓派上规划要十几秒，车停在 QR 等着。
- 重新规划不出来：车停在 QR，不乱走。

在电脑上模拟过这次的情况：原路线 TEMP→RAW 是沿左边车道往北，正好从左上角那个没扫到的圆柱上开过去；QR 扫到它以后，新路线改成走中间。

## 2. 回启停区冲出去 → 回家前先定位

以前是照原路线一直走到启停区，到了再对准。误差攒下来，最后几步就可能把车送出启停区。

现在最后回启停区那一段：车头转好、离启停区还有 80 厘米以内的地方先停下，扫一圈，和出发时在启停区里扫的那一圈对齐(里面有那几个障碍物，还有场边的桌椅、二维码板)，算出车实际在哪，再按实际位置走进启停区(前后、左右的先后顺序和原路线一样)，最后再扫一次确认，最多修 3 次。
- 定位对不上(场里变化太大)，或者算出来要走的距离比原路线多出 25cm 以上(不像是对的)：不信它，按原路线剩下的几步走，到了再对准一次(和 v12 一样)。
- 电脑上模拟：离启停区 20~50 厘米、实际位置偏 4~9 厘米、车头歪 1.5~3° 的情况，定位误差都在 1~2mm。

## 可以调的(在 map_config_start2_roi.json 里加，不加就用默认值)

| 键 | 默认 | 意思 |
|---|---|---|
| rescan_stops | ["QR"] | 到哪些停车点再扫一次 |
| station_new_mm | 200 | 离已知障碍物超过多少毫米才算新的 |
| home_approach | true | false = 关掉回家前定位(到了启停区再对准，和 v12 一样) |
| home_approach_mm | 800 | 离启停区多远开始定位 |
