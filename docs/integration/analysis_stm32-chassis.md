# STM32 底盘运动控制分析报告（chassis.c / main.c 解析器 / hwt101.c / 用户调好的参数）

**结论：** 车上没有任何位置反馈，只有陀螺仪。距离是把下发的速度指令积分出来的，指令走完就停，不靠编码器判断到位。肉眼看到的抖动最可能来自四处：①转弯（包括 F/S 走完后自动补的小转弯）末段在 0 和 ±8 rpm 之间来回切换；②转弯刹车的减速要求超过驱动器斜坡；③横移前馈在开始减速那一刻跳一下；④横移航向环用硬死区、不滤波、每周期都重发指令。三段运动都是梯形速度曲线，拐点处加加速度无穷大。我没有改仓库里的任何文件，只在 scratchpad 写了一个模拟程序。

## 1. F / S / R 是怎么执行的

### 1.1 协议和解析（main.c）
- 指令格式是 `F <mm> [rpm]`、`S <mm> [rpm]`、`R <deg>`，在 main.c:843-884 解析：
  - 距离和角度都用 `strtol` 读，**只认整数**，`R -1.4` 会回 `ERR ARG`（main.c:849-857）。
  - 范围：F/S 为 ±2500 mm，速度 5..300；R 为 ±180°，`R 0` 等于 HOME（main.c:862-870）。
  - 不带速度时用 `ROUTE_SPEED 220` / `ROUTE_STRAFE_SPEED 170`（chassis.h:39-40）。实际上树莓派总是带速度：route 150 / strafe 140（auto_run.py:59-62, 227）。回家对准的小步修正用 `home_fix_rpm=60`（map_merge_live.py:323, 358）。树莓派发 R 前会先取整：`int(round(-th))`（map_merge_live.py:350）。
- 应答：`Link_Done` 回 `DONE t=.. e=..`、`ERR ABORT` 或 `ERR STALL`（main.c:680-695）。`'!'` 在中断里置 `car_abort`（main.c:629-632）。
- **隐患：** main.c:639 的注释说"忙时来的新指令直接丢掉"，但 `link_ready=0` 在执行**之前**就清了（main.c:713-714）。所以运动中收到的新一行会被缓存一条，等当前动作做完再执行。如果树莓派那边 stm32_link.py（不在仓库里）超时后重发，车会把同一个动作走两次。
- 运动期间 `Link_Poll` 一直阻塞，主循环 100 ms 一次的 YAW100 遥测这段时间不发（main.c:218-232）。

### 1.2 公共部分
- 轮子用速度模式驱动：`Wheels_Vel`（chassis.c:900-914）。
  - 每轮 `Emm_V5_Vel_Control(.., (uint16_t)(|s|+0.5), SC_EMM_ACC=200, sync)`，**速度只能是整数 rpm**。四条指令之间隔 2 ms，最后广播 `Synchronous_motion` 让四个轮子同时生效。
  - 驱动器内部斜坡：acc=200 时约 357 rpm/s（每 1 rpm 需 (256-acc)×50 µs = 2.8 ms），和测试假车用的数（test_chassis.c:33）一致。
- 控制周期：`HAL_Delay(SC_PERIOD_MS=20)`，HAL 实际多等 1 ms，加上发指令约 8-10 ms，**实际约 33 ms（约 30 Hz）**。代码里 Yaw_Guard 的注释（chassis.c:77）也写的是约 33 ms。dt 用 HAL_GetTick 实测，所以积分没问题。
- **反馈只有陀螺仪：**
  - 航向用 HWT101 的 0x53 帧（hwt101.c:92-115），分辨率 0.0055°。
  - 0x52 角速度帧解析到了 `hwt101_dbg.gyro_dps`（hwt101.c:116-120），**但 chassis.c 没用它**。
  - 运动中不读轮子编码器。其实读的条件已经有了：`Mot_Query`/`Car_Motor_Query`（chassis.c:1435-1478）可以读 Emm 的 0x36 实时位置，arm.c:376-396 读升降电机就是这么做的。
- 防干扰措施：
  - `Yaw_Median5`：5 次读数取中值，耗时约 48 ms（chassis.c:50-75），每条 F/S 开始和结束各做一次。
  - `Yaw_Guard`：读数一下跳 >3° 的帧先丢掉，最多连丢 2 次（chassis.c:80-93）。

### 1.3 F：`Car_Straight_Closed`（chassis.c:934-1093）
- **速度规划：** 先 `v += SCACC·dt` 加速，到 vmax 后匀速，再用 `v ≤ sqrt(2·a·rem)` 按剩余距离刹车，最低 `SC_MIN_RPM=6`（989-1002）。纯梯形，没有 S 曲线。
- **怎么判断走完：** `done += v·3200/60·dt`，`rem = target − done ≤ 0` 就 break（981-986）。也就是**按下发速度积分出的脉冲数判断，不看编码器，也不按时间**。
- **结束流程：** 发 0 速 → 立即 `Stop_Quick`（Emm Stop_Now）→ `SETTLE` 60 ms → 再取一次 Median5 → 学习偏向补偿 → `Heading_Fix`（1074-1092）。
- **航向 PI（v12a）：**
  - `err_f` 一阶低通，`SCLPF=0.08 s`（1011）。
  - 连续死区 0.05°（1013-1016）。
  - 积分用滤波后的误差，不设死区，`SCKI=1`，积分上限 ±6 rpm（1018, 1030）。
  - P 增益 `SCKP=2` rpm/°。
  - 加偏向前馈 `g_sc_bias[di]·v`（1033）。
  - 纠偏量变化速度限制 `SCRL=30` rpm/s（1034-1040）。
  - 纠偏量上限 0.25·v（1029, 1041）。
- **轮速：** 右侧 = v+corr，左侧 = v−corr（1052-1055）。取整后四轮都没变就不重发，但最多隔 10 个周期补发一次（1056-1071）。
- **偏向学习：** 巡航阶段累计 PI 输出/v，结束时车头误差 <2° 才更新，`b += 0.6·mean`，上限 ±0.05（1045-1050, 1083-1090）。
- **`Heading_Fix`：** 车头误差超过 `ALTOL=1.5°` 才绕车中心转回 `yaw_target`（917-930）。

### 1.4 S：`Strafe_Run`（chassis.c:1142-1352）
- 速度规划和 F 一样，只是用 `SSACC`（1201-1214）。
- **航向 PI 没有 v12a 那些改进：**
  - 硬死区 0.2°（1242-1245），没有滤波，没有变化速度限制。
  - `SSKP/SSKI`，积分上限 ±8 rpm，纠偏量上限 0.5·v（1240-1251, 1274-1276）。
- **前馈：**
  - `Strafe_Lookahead` 往前看 `SSLEAD` 秒，预测那时的速度和加速度（1106-1139）。
  - 根据预测加速度 `al ≥ 0` 选 CA，`al < 0` 选 CD，`ffu = −ca·v^1.5/k_turn`，上限 ±30 rpm（1253-1260）。
  - 前馈增益实时学习由 `SSRT` 控制，用户设成 0，已关闭（1264-1272）。
- **前后漂补偿：** `fc = −drift·v·FPPM/ppm`（1279）。
- **每个周期都 `Wheels_Vel`**，不做"没变就不发"（1286）。结束流程和 F 相同（1299-1351）。

### 1.5 R：`Car_TurnBy_Center` → `Turn_To` → `Car_Turn_Closed`（chassis.c:792-814, 718-765, 579-715）
- **目标航向：** `yaw_target + delta`，按累计目标转，不是按当前测量值。如果实测和记录差超过 6°，改按实测算（801-808）。
- **加速和刹车：**
  - 加速 `TCA=400` rpm/s。
  - 想要的速度 `want = min(sqrt(2·TCD·a/k), TCKP·a, TCV)`，下限 `TC_MIN_RPM=4`（653-656）。
  - 减速时直接 `v = want`，不受减速度限制（657-665）。
- **延迟预测：** `Turn_Inflight` 用纯延迟模型 `TCLAG=0.16 s` 估算"已经发出去、还没转出来"的角度（555-577, 625）。
- **到位判断：** 预测误差 ≤0.6° 时发 0 速；实际误差 ≤0.8° 且连续 3 个周期才算到位（629-644）。
- **其它：** 预测冲过头就先把速度清零再反向（648-651）；超时 5 s；卡住检测（612-622）。
- **转弯时叠加平移（turn_comp）：** `u = −ω·PVB·13.67·60/3200`（696-702）。
  - 用默认 PVB=103 算，u ≈ −0.97·w。结果是**前轮 ID1/ID2 几乎不转（约 0.03·w），后轮 ID3/ID4 转约 1.97·w**。
  - 模拟里 R 90 时后轮达到 138 rpm，前轮约 2 rpm。
- **后备方法：** 闭环转完后误差还 >`TURN_TOL_DEG=1.0`，就用位置模式再修，最多 6 次（726-757）。

## 2. 抖动可能的来源（按可能性排序）

我在 scratchpad 写了一个模拟：复用 test_chassis.c 的假车，另加 100 Hz 采样保持的陀螺仪噪声、横移自转模型（用户的 CA/CD）和 x/y 里程，位置在 `/tmp/claude-0/-home-user-car111/1361d234-10df-5c5b-952c-32b74baba831/scratchpad/sim/sim.c`。假车是理想化的，下面的数字只能说明趋势。

1. **转弯末段来回切换**（chassis.c:629-666, `TC_MIN_RPM 4`, `TC_STOP_DEG 0.6`, 反向清零 648-651）。
   - 只要预测误差 >0.6°，速度就至少给 4 rpm；加上平移补偿，后轮实际约 ±8 rpm。到了 ≤0.6° 立刻给 0。
   - 模拟 R 90（无噪声）：末段约 0.5 s 内在 0 和 ±8 rpm 之间切换 9 次，最后误差 0.35°。
   - **F/S 走完后误差 >1.5° 时自动补的小转弯也走这段逻辑**，所以每次停车后都可能"抽几下"。
2. **转弯刹车太猛。**
   - 误差小于约 26° 以后，`TCKP·a` 这一项比 sqrt 刹车曲线小，所以 `TCD` 实际上不起作用。
   - 这时减速要求 ≈ TCKP·k·v ≈ 6.3·v rpm/s，v=80 时约 500 rpm/s；后轮是 2 倍，约 1000 rpm/s。驱动器斜坡只有 357 rpm/s，最后由驱动器限速。
   - 实际刹车和 Turn_Inflight 的纯延迟模型对不上 → 冲过头 → 反向补，接上第 1 条。
   - 模拟里后轮每周期掉 28 rpm（138→110→89→70）。
   - 前轮几乎不转、后轮出全力，负载不对称，也可能引起打滑和抖动。
3. **横移前馈在开始减速时跳一下**（chassis.c:1256：`al≥0` 用 CA，`al<0` 用 CD，而 CA≈2-3×CD）。
   - 模拟 S ±300：一个周期内左右差速跳 4.8-6.0 rpm，相当于横摆角速度指令突然变 10-12°/s。
   - 300 mm 的横移达不到 140 rpm 匀速，三角形曲线的峰值约 104 rpm，所以这一跳正好发生在**最高速**时。
4. **横移航向环太粗糙。**
   - 硬死区 0.2°，而注释说陀螺仪噪声约 0.35°（chassis.c:283），误差会在死区内外反复进出。
   - 不滤波，每周期都发指令（1286）。
   - 每个轮子的 `sl·v+corr+fc` 单独取整，±1 rpm 来回跳。
5. **直行环（v12a）相位裕度偏低（这是估算，没实测）。**
   - P 环交越频率 ≈ 2·SCKP·k/2 = 2.1·2 ≈ 4.2 rad/s。
   - 总延迟 ≈ 0.12-0.16 s 车身 + 0.08 s 滤波 + 约 0.03 s 采样 ≈ 0.27 s，相位滞后约 65°，裕度约 25°。不开滤波时约 45°。
   - 可能出现 0.5-0.7 Hz 的慢速左右摆。SCRL 限制了摆幅。
   - 理想车模型里直行很干净：每周期差速变化 ≤1 rpm，没有符号翻转。只有 v12 不滤波且噪声 0.15° 时出现 1 次翻转，指令数从 49 增加到 56。所以直行在模拟里不是主要问题。
6. **整数 rpm 量化。** 1 rpm ≈ 前进 4.1 mm/s；左右差 1 rpm ≈ 2.1°/s。驱动器 2.8 ms 就跟到位，每次改指令在 30 Hz 下都是一个小台阶。
7. **梯形曲线拐点**：起步、进入匀速、开始减速、停车，加加速度都是无穷大。启动第一个周期直接 6 rpm 起步；停车时从约 6 rpm 直接 Stop_Now（1074-1076, 1299-1301），这一项影响不大。
8. 没有微分项，不存在"微分放大噪声"的问题。
9. 还有一个假设：步进电机中频共振（几十到 150 rpm）。可以架空车轮、单轮恒速跑来验证。

## 3. 最终位置为什么不准

- **开环距离：** 按"下发速度积分 = 目标×ppm"停车。Emm 是闭环步进电机，轮子转多少基本等于下发多少，所以误差主要来自三方面：
  1. **打滑**：加减速段打滑和速度、加速度有关；横移 ppm 比前进多约 7%。用一个距离标定出的 ppm 会带来随距离变化的误差 → 建议改成"ppm·d + 偏移"两点标定。
  2. **航向误差造成侧偏**：偏 1° 走 1000 mm 侧偏约 17 mm。
     - R 到位精度只有 ±0.8°（TC_TOL_DEG），后备方法 ±1.0°。
     - Heading_Fix 只在误差 >1.5° 时才修。
     - R 只认整数度，树莓派也会先取整。
     - 模拟里 `R -2` 最后还剩 0.4-0.6°。
  3. **转弯平移补偿可能不准**：PVB/PVL 用的是固件默认 103/0，树莓派没下发。树莓派笔记里实测转轴是"后 93-109、左 12"。如果这是没开补偿时测的，12 mm 的 PVL 误差会让车中心每转 90° 偏约 2·12·sin45° ≈ 17 mm。可以用 chassis.c:547-548 的公式实测确认。
- **停车过冲很小**：最后一个周期最多多走 v·dt ≈ 6 rpm × 33 ms ≈ 0.8 mm。
- **每条指令有固定开销**：STM32 端约 175 ms（开始 Median5 48 + 停车约 16 + SETTLE 61 + 结束 Median5 48），再加树莓派往返 `cmd_overhead_s=0.25`。所以把最后的接近拆成很多小步会很慢。
- **精准慢速最终接近的几种做法：**
  - (a) 速度 ≤ 阈值时自动进入精度模式：更小的加速度和 S 曲线、最后几 mm 低速爬行、SETTLE 加长、ALTOL 降到约 0.5°。树莓派做修正时本来就发 60 rpm，**不用改协议**。
  - (b) R 支持 0.1° 分辨率，同时让转弯末段平滑。
  - (c) 动作前后读四个轮子的 0x36 位置，确认真正执行的脉冲数（能发现丢步和堵转，但测不出打滑）。
  - (d) 用陀螺仪积分估算侧偏 `y_est = ∫v·sin(err)dt`，结束时补一小段横移，或者在 DONE 里报出来。但 `parse_done` 在不在仓库里的 stm32_link.py 中，不知道它能不能容忍新增字段。
