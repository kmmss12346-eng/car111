# 路线规划审查：route_plan.py、test_route_margin.py、map_config_start2_roi.json，以及 map_merge_live/auto_run 怎么调用规划

按要求没有改任何仓库文件。下面的数字来自草稿目录 `/tmp/claude-0/-home-user-car111/1361d234-10df-5c5b-952c-32b74baba831/scratchpad/rp/` 里的只读脚本：用用户 10 月 6 日的配置跑了 `rp.plan_mission`，再按 `auto_run.flatten` 实际发给 STM32 的指令序列（丢掉小于 20mm 的 F/S）重放，计算真实车身到各区域的距离。真实车身是 290×260 的矩形，加左侧雷达圆盘：中心在前 22.5、左 134.8，半径 35.2，正好比车身突出 40mm。

## 0. 结论摘要
- **零误差时，没有哪个停车点让车压线。** 最近的是 ROUGH/TEMP：真实车身离工位区 60mm，实际执行时只有 45mm（原因见第 4 条）。
- **路线本身离线不远。** 无障碍时，直行段真实车身最近：黄区 47mm、暂存区 45mm、粗加工区 53mm。转弯扫过的圆离黄区至少 118mm，转弯不是主要风险。
- **主要风险是航位推算误差累积。** 这版代码在行驶中没有任何雷达位置修正：`relocalize` 只在 map_merge_live.py:16 导入，从来没被调用。蒙特卡洛估计（误差模型是我假设的，不是实测）：常规误差下，整场某处压线的概率约 0.69；乐观误差下约 0.09。每个停车点加每次转弯后都用雷达修正一次，降到约 0。
- **执行器和规划器之间有一个实际 bug。** 停车点不在 25mm 栅格上（ROUGH y=340、TEMP x=340、第二站 (2208,233)），规划会生成 8～15mm 的补偿移动。`auto_run.flatten` 把小于 20mm 的 F/S 直接丢掉，不补回去（auto_run.py:14、42-43）。后果有两个：
  - 车实际停在离工位区近 15mm 的地方。
  - 偏移有时会累积。在 sim 障碍物 + yellow_margin 50 的情况下，车离黄区只剩 8mm，回启停区时冲出场地南边 17mm；不丢小移动时分别是 30mm 和 5mm。
- **只加大黄区余量会更糟。** 暂存区、粗加工区、原料盘、场地边都没有硬性余量，`zone_margin_mm` 没有任何代码读取。设 `yellow_margin_mm` = 50 后，车被挤到离暂存区 20mm、离粗加工区 28mm。设 60～80 时，因为停车点本身离黄区不到这个距离，去这些点的每一段都整段退回到一半余量。
- **工位里的底盘微调不经过规划检查。** 圆环间距 ±150、对准时前后再挪最多 60、横移最多 40（mission_hooks.py:100-108）。在零误差下就能把车送到离线 0～5mm。

## 1. 规划器怎么建模

**数据流：**
1. map_merge_live 的 `plan_route()`（map_merge_live.py:178-227）准备输入：
   - 起点：用第一次扫描的车头方向和第二站的实际位姿算出 `plan_start`、`start_pivot` 和 `turn_back`（187-195）。
   - 任务：`START` 按 `start_zone` 换成 START2 或 START1（204）。
   - 障碍物余量依次试 (60, 看不清的再 +80) → (40, +40) → (20, 0)（209-216）。
   - 调用 `plan_mission(dict(mission_cfg(), margin_mm=mg), obs, plan_start, mission, start_pivot=...)`（213）。`mission_cfg()` 就是原始配置加上校验过的车长车宽（175-177）。
2. `Ctx.plan()`（395）把 `(turn_back, legs, reason)` 交给 auto_run。auto_run 的 `run_mission` → `flatten` → `drive` 一条条发 `link.move`。
3. 到 QR 再扫一次时，如果有新障碍物，就从配置里的 QR 停车点坐标重新规划剩下的路线（655-667）。
4. `Motion` 只用来估算时间：A* 的代价、`route_stats`、auto_run.py:274 的预计用时。

**route_plan 内部：**
- 场地是 25mm 栅格，A* 状态是 (i, j, 上一步方向, 车头 4 个方向之一, 已横移格数)，代价是“秒”（311-366）。
- 每段先按 `yellow_margin_mm`、再按一半、再按 0 规划，一段失败就整段退一档（438-441, 476-488）。
- 吸附栅格和检查停车点都用余量为 0 的那个规划器（442）。
- `plan_mission` 依次试：整段封死有障碍物的车道（误差容忍 80mm）→ 容忍 0 → 不封车道 → 取消横移上限（506-540）。

## 3. 行驶和转弯中能保证多少余量，误差会怎样

**规划能保证的下限：**
- 平移：
  - 黄区：外框 ≥30。退档时只有 15 或 0。换算到真实车身，前后 ≥35，左右 ≥50；退到 0 时只剩 5/20。
  - 暂存区、粗加工区、原料盘、场地边：真实车身只有 5（前后）/ 20（左右）。
- 转弯：车角扫过的圆离任何区域 ≥20mm，和 `yellow_margin_mm` 无关。auto_run 丢掉小移动会把这个余量再吃掉几毫米（见过 40→34）。

**实际算出来的路线（按 auto_run 的发法）：**
- 无障碍：68 秒，10 次转弯，基本走外圈，在 x=2100、y≈2108、x=325、y≈333 这几条线上。直行最近：黄区 47、暂存区 45、粗加工区 53、原料盘 92。转弯最近：黄区 118、墙 30。
- 有 sim 障碍物（3 个障碍物把外圈封死，只能走 400mm 宽的中间车道）：81 秒，18 次转弯，8 段里有 7 段退到 15mm。直行离黄区最近 37；转弯离黄区 47、离暂存区 30、离原料盘 28。

**误差 ±30mm、±2° 的情况：**
- 转 2° 会让车身在各方向多伸出约 5mm（145·cos2°+130·sin2°−145 ≈ 4.4），所以平移需要至少 35mm 静态余量，转弯需要至少 30mm。
- 无障碍路线：工位附近还剩约 10mm，能过。
- 有障碍路线：规划只保证 15mm，转弯只保证 20mm，理论上不够。

**但航位推算给不了 ±30mm：**
- 起步时车头方向的系统误差 ε 会让每段直行横向偏 L·sin ε。最长的直行段 1775mm：1° 就偏 31mm，2° 偏 62mm。
- 蒙特卡洛的误差模型（是我的假设）：
  - 起点 σ8mm。
  - 车头系统偏差均匀分布 ±1°；每条指令再有 ±1° 的残差（对应 STM32 的 TURN_TOL / ALIGN_TOL，chassis.c:264, 267）。
  - 前进距离比例误差 σ1% + σ3mm，侧滑 0.5%；横移比例误差 σ2%，前后串动 2%。
  - 每次转弯中心偏 σ5mm。
- 结果（基线路线）：

| 情况 | 到各停车点位置误差的 95 分位（mm） | 整场压线概率 |
|---|---|---|
| 常规误差 | QR 38 / RAW 85 / ROUGH 94 / TEMP 101 / START2 123 | **0.69** |
| 乐观误差（参数约为一半到三分之一） | QR 23 / RAW 42 / ROUGH 46 / TEMP 51 / START2 59 | 0.09 |

- 最容易压线的地方：底边车道 y≈333 从右下、左下黄区下面经过的那一段（雷达在北侧），以及西边车道暂存区附近。

## 5. 启停区 1 要做什么才能用
- **规划器本身没问题。** 起点设在 START1 就能规划出来：68 秒，10 次转弯，最近距离和 START2 差不多（直行离黄区 55、离暂存/粗加工 37～45；转弯离黄区 ≥124）。
- **配置必须改，否则不能用：**
  - `start_zone`=1。
  - 车的起点 `car_x_mm`/`car_y_mm`/`car_yaw_deg` 改成 **2250/2250/180**（车头朝西）。这个起点被扫描地图和 `plan_start` 共用（map_merge_live.py:187-195）。
  - `stops.START1` 的车头方向要和起步车头一致，改成 **180**。回家对准是和第一次扫描对齐的，现在配置里是 90，相差 90° 会对不上。
- **现在的配置直接用 START1 很危险：** START1 车头朝北时，第二站动作（左 42、前 83、顺时针 60）会让车头冲出北边 78mm，转的时候扫出 128mm。
- **车头朝西是 START2 绕场地中心转 90° 的等价位置**，第二站动作可以原样用：车停在 (2167,2208,120)，转回 180° 时和 START2 一样有一个车角超出北边约 3mm。雷达在车左侧，正对场内。
- **还不能确认的：**
  - 车上的 `pose_fix.refine_second`、`merge_stations`、ROI 有没有写死 START2 的几何关系（这些代码不在仓库里）。
  - STM32 的 P2 指令写死了动作，不要开 `second_use_p2`。
  - `home_cut` 要求最后一次转弯离终点 ≥800mm，START1 朝西时满足（最后一次转弯后直行 1925mm）。

## 其他小问题
- 停车点放不下时，提示一律写“被障碍物挡住”，哪怕原因是出场地（route_plan.py:493-497）。
