# car111 更新包 1010j：全流程整合

这一包把整场比赛连起来了：屏幕选启停区 → 自动扫描、预先规划 → 按屏上 START 一键出发 → 每个停车点雷达重定位 → 做任务 → 时间不够提前回家 → 回启停区精确对准 → 收臂、升降停 60mm。
**树莓派和 STM32 都要更新。** 只更新树莓派也能跑（新功能会自动退回旧做法），但屏幕选区、PARK、小数转角、精确模式这些要新的 STM32 程序。

所有功能都只在电脑上的模拟里测过（树莓派 416 个测试、STM32 主机测试全过），**没有上车跑过**。请按第四节一步步上车验证，有问题把终端日志发给我。

## 一、这次改了什么

### 1. 导航（auto_run.py、map_merge_live.py、新文件 reloc.py）
- **修了回家冲出场地的 bug**：以前回家前的雷达定位中途失败，会接着执行原路线剩下的指令，车多走 700 多 mm 冲出场地。现在定位失败就重新测或原地停下，**绝不再盲走原路线**。
- **回家更准**：新加了一个 PREHOME 停车点（启停区 2 是 (2250,400)，启停区 1 是 (2000,2250)），离家 250mm 内最后再定位一次，然后慢速（60 转，STM32 精确模式）对准，最多修 2 轮。每一步都先检查车身（含雷达）不会出场地；定位一直失败时宁可少走 15mm，也不越界。
- **每个停车点先用雷达重定位再修正**：用开头两次扫描做参考，快速 ICP（只用 numpy），算出车实际在哪，偏了就用小转角、60 转横移修回来。日志里有 `◆ 雷达定位 …`，显示用时、残差、对上的点数。
- **小于 20mm 的移动不再丢掉**：以前会悄悄丢，误差一路累积；现在余数带到下一条指令里，每段都停到停车点上。
- **时间不够从当前点直接回家**：开跑前就把"从每个停车点回家"的路线算好，每离开一个停车点前问一次时间够不够，不够就直接回家。
- **支持启停区 1**：车头朝西（就是启停区 2 绕场地中心转 90°），第二站动作和启停区 2 一样，START1 车头 180°，自动换算，不用改配置。
- **一键出发**：终端输入 `race`（或配置里 `race_auto: true` 开机自动）→ 屏上选 1 或 2 → 把车放好别动 → 程序自动扫描、预先规划，屏上显示 `READY` → 按屏上 START 开跑。**开跑后不用再敲 y，也不用碰电脑。**
- **15 秒不动规则**：开跑后扫描、规划、定位这些车不动的时候，手臂每 5.5 秒轻摆一下（ID1 ±3°，不到 1 秒）。
- **退出程序时**（q、Ctrl+C、关窗口）自动收臂、升降停 60mm。急停以后不会自己动，要你确认车旁没人后输入 `park`。

### 2. 路线规划（route_plan.py）
- **硬余量**：黄区 30mm（实在走不通最低降到 15mm，**不会再降到 0**），暂存区/粗加工区 30mm，转盘按它可能出现的整个范围（中心 x 1100~1300）再留 30mm，场地边 30mm（启停区里除外，要开进角落）。按真实车身 290×260 加左边雷达算。
- **规划快了很多**：电脑上一次整场规划从约 13~15 秒降到约 1 秒（树莓派上大约几秒，看日志里的"规划用时"）。
- 每段都精确停到停车点，不再产生 8~15mm 的补偿小动作。
- 两个启停区、有障碍物和没有障碍物都测过能规划出来。

### 3. 整场任务（mission_hooks.py 等）
- **开跑前清掉旧任务码**（`QR CLR`），屏上显示 `---` 直到扫到新码。
- **扫码读不到就前后挪着找**：扫码器在车右后方（离车后边约 20mm、离右边约 40mm），读不到就前后挪（车头朝北时依次 F 125、185、65、245mm），挪前检查不会碰障碍物、不压线，**找完一定挪回停车点**。还没读到，到后面的停车点再问一次。
- **按剩余时间决定还做不做**：每个物料开始前都算"做完这个 + 回家"够不够，不够就停手，让车回家。
- **暂存区第二批找不到同色物料就跳过**（规则只许码垛，平放 0 分），也不算进放置数。
- 屏上任务码补上 `+`：第一行 `156+123+`，第二行 `516+231`。结束时屏上直接显示 `GRAB n`、`PLACE m`（正确个数）。
- **噪声跳一下不再当成发散**：要连续两次变大才算；比赛中不会把存好的 J 从 servo_cal.json 里删掉。
- **车身斜了的提前补偿**：到粗加工区/暂存区看三个环时算出车身和圆环那一排的夹角，提前把手臂伸缩补到每个环；**斜 3° 以上日志里出 ★ 提醒你把车摆正**。
- `ring_strafe_max_mm` 改成 20（旧配置里的 40 会被 apply_mission_config.py 自动改掉），工位里车轮横移离白区更远。
- **先动车轮的开关**：你说想"到附近先慢慢动轮子，实在不行再动爪子"。我做了，但模拟里它比默认（先动手臂）更慢、失败更多，原因是车轮只能管沿圆环那一排的方向，离圆环远近还得靠手臂伸缩，而且小步底盘不准时容易被判成发散。所以**默认还是先动手臂**，你可以上车对比：`mtest TEMP 1 force wheels`（先动车轮）、`mtest TEMP 1 force nofilt`（不用测量滤波），结束时会打印"这次用时"，比一比再决定。

### 4. STM32 底盘（chassis.c、main.c）
- **转弯快停时平滑减速**，不再在 0 和 8 转之间来回抽；转完误差约 0.5°（以前 0.8°）。
- **横移去掉了减速时的前馈突变**，航向环加了滤波，横移时车头不会突然一甩。
- **精确模式**：速度 ≤ 60 转的移动（回家对准、重定位修正都用 60 转）加速更柔、最后慢慢爬到位、车头偏 0.5° 就修。`SET PSPD 0` 关掉。
- **R 支持小数**：`R -1.4`、`R 12.5`。`R 0` 还是 HOME。
- 新参数（`GET` 能看到）：TCSTOP、TCTOL、TCMIN（转弯末段），SSLPF、SSRL、SSFFR（横移），PSPD、PACC、PMIN、PSET、PALTOL（精确模式）。

### 5. STM32 屏幕/升降/扫码（arm.c、hwt101.c）
- **开机屏上显示选启停区**：左半边大按钮"1"、右半边"2"。选完显示 `ZONE n`、状态行、大 START 按钮和小 BACK 按钮（BACK 回去重选）。按下、松开都在同一个按钮里才算，防误触。开跑后锁住，再碰屏没用。
- 新指令：`ZONE?`、`ZONE ASK`、`ZONE 1`/`ZONE 2`（终端代替触摸）、`ZONE MSG 文字`、`ZONE LOCK`。
- **PARK**：收臂并把升降停到 60mm。
- `LIFT?` 回复多了 `BOOT=…`：开机是怎么认高度的（ENC/POS = 编码器认准的；NOCAL/NOENC = 没认准，当作 60）。
- **车在走的时候扫到的码也会记住**（以前车动的时候收到的码可能丢）。
- 比赛时屏幕布局变了：任务码一行 8 个大字；阶段 t1、提示 t4 挪到右边；B1/B2 挪到右上角。

## 四、上车测试（按顺序，每步通过再做下一步）

### 第 1 步：STM32 基本检查（车架空或放地上都行）
| 输入 | 应该看到 |
|---|---|
| （开机后看屏） | 屏上是选启停区的页面：左"1"、右"2" |
| `get` 或 `arm GET` | 多了 `PSPD=60`、`TCSTOP`、`SSLPF`、`PACC` 等新参数 |
| `arm LIFT?` | `LIFT 1 60… BOOT=POS`（或 ENC）。如果是 NOCAL/NOENC，说明开机没认准高度，先 `arm LIFT ZERO` 标一下 |
| 在屏上按"1"，然后输入 `arm ZONE?` | `ZONE 1 0`；屏上显示 ZONE 1 和 START 按钮 |
| 按屏上 START，再 `arm ZONE?` | `ZONE 1 1`，状态行显示 GO |
| `arm ZONE ASK` | 回到选区页面 |
| `arm PARK` | 手臂收回，升降停到 60mm，不碰任何东西 |

如果屏上点了没反应：检查屏的 TX 线是不是接到 PD6。点不了也能用终端 `zone 1` / `zone 2` 代替。

### 第 2 步：底盘（车放地上，周围留空）
| 输入 | 看什么 |
|---|---|
| `send R 90`、`send R -90`、`send R 180` | 转到最后是一次平滑减速，不再来回抽几下；DONE 里 `e=` 在 ±50 以内（0.5°），每次不超过约 2.5 秒 |
| `send R -1.4` | 小数转角能转 |
| `send S 300 140`、`send S -300 140` | 横移快停的时候车头不突然一甩 |
| `send F 30 60`、`send F -20 60` | 精确模式：起步柔、最后慢慢到位，距离差 1mm 左右 |
| `send F 1000 150` | 和以前一样稳 |
| 车走的时候按急停 | 马上停，回 ERR ABORT |

转弯最后爬得很慢：`set TCLAG 0.12`；转过头又转回来：`set TCLAG 0.2`。调好以后把这个值写进配置文件的 `stm32_params`，每次开机自动发。横移结束时车头比以前偏得多：`set SSLPF 0`。

### 第 3 步：扫码
1. 码板贴东墙，车手放在 QR 停车点 (2100,1200)，车头朝北。
2. 码板分别放在 y=1100、1200、1300（板中心），每次输入 `mtest QR`。
3. 看：先原地查，读不到就前后挪（日志里有挪多少），读到后挪回原处。屏上显示带 `+` 的任务码，第一行 `156+123+` 要完整显示。
4. 车走的时候扫码：`arm QR CLR`，然后让车开过码板（`send F 300`），再 `qr`，应该读到。

### 第 4 步：工位（你已经测过，这次主要看新东西）
1. `mcode 156+123+516+231`
2. 车故意摆斜 3~5° 停在暂存区，`mtest TEMP 1 force`：日志里会报车身斜多少度，3° 以上有 ★ 提醒；到 1、3 号环第一次测到的偏差应该只有几 mm。
3. 对比先动车轮：`mtest TEMP 1 force wheels`、`mtest TEMP 1 force nofilt`，每次结束看"这次用时"和放得准不准。
4. `mtest TEMP 2 force`：第二批码垛；如果某个颜色下面没有同色的，会跳过，不平放。
5. 工位里如果日志出现"车轮横着也挪到上限"，说明停车点离圆环那一排不合适，告诉我，**不要把 ring_strafe_max_mm 改大**。

### 第 5 步：启停区 2 整场（先跑你熟悉的）
1. 输入 `race`。
2. 屏上选 2，把车放进启停区 2（车头朝北），手离开。
3. 看屏上状态：`SCAN` → `PLAN OK` → `READY`。
4. 按屏上 START。**之后不要碰车和电脑**，只看。
5. 看日志：每个停车点都有 `◆ 雷达定位`；扫码；工位；时间不够时有"直接回家"；最后 PREHOME 定位、慢速对准进启停区；收臂、升降 60；屏上 GRAB/PLACE。
6. 跑完把整段终端日志发给我，尤其是：每次雷达定位的用时和偏差、规划用时、回家后车的位置、总用时。

### 第 6 步：启停区 1 整场（从来没跑过，要特别小心）
1. 第一次先跑到第二站就停：`race` → 屏上选 1 → 车放进启停区 1，**车头朝西** → 等 READY → 按 START，旁边有人准备随时按急停（终端 `abort`）。
2. 看第二站：车往左移、前进、转 60°，不撞北边墙；日志里没有"第二站：按障碍物校正的车位和雷达整圈对齐的差得多"这种警告。
3. 第二站没问题再跑完整场，同样把日志发给我。

## 五、要注意的地方
- **回家停的位置**：为了不出场地，车身最后离场地边约 10mm，靠场内那一边可能有 10~15mm 在启停区外面。规则没写清"回到启停区"怎么算，最好赛前问一下裁判；要调就改配置 `home_goal_edge_mm`。
- **雷达定位离起点远时可能对不上**（原料区、暂存区离起点 2m 以上，或者场地四周没有墙）。对不上就不修，只靠底盘走，日志会写出来，不危险，但那一段的误差和以前一样大。场边有人走动也会影响。
- **时间**：两批全做完在 3 分钟里基本做不完。程序会按剩余时间自动决定做到哪一步就回家。跑完一次后看 START 时打印的每个物料、每个停车点的用时，告诉我，我再调估计值（`work_item_s`、`home_margin_s`）。
- 屏幕选区等待的时候，程序只用 `ZONE MSG` 往屏上写字；如果你在这时候用 `arm SCR …` 写屏，选区页面会关掉、触摸失效，要重新 `race`。
- 爪子里可能夹着物料时，`park` 不会降升降（60mm 正好是放进转盘的高度，会压上去）。先 `arm CLAW O`。
- 第二站原地转回来时车角会伸出东边线约 3mm（以前就这样，那时车还没离开启停区，不算违规）。如果场边有实体墙，把车往西放几 mm。
